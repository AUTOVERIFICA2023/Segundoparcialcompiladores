2.1 ¿Cómo piensa realmente una aplicación web?

Antes de entrar a código, el estudiante debe entender el pensamiento detrás del sistema.

3. Rutas web: lenguaje natural vs sintaxis Spring

Una ruta es la dirección que el usuario escribe o visita en el navegador. En Spring, esa ruta se conecta con un método Java.

Movimiento del usuarioLenguaje naturalSintaxis Spring¿Para qué sirve?
Abre una página“Quiero ver la lista de estudiantes”.@GetMapping("/estudiantes")Mostrar información.
Abre un formulario“Quiero registrar un nuevo estudiante”.@GetMapping("/estudiantes/nuevo")Mostrar formulario vacío.
Envía datos“Ya llené el formulario, ahora guarde”.@PostMapping("/estudiantes/guardar")Recibir y guardar datos.
Edita un registro“Quiero modificar el estudiante con id 5”.@GetMapping("/estudiantes/editar/{id}")Buscar por ID y mostrar datos.
Elimina un registro“Quiero borrar el estudiante con id 5”.@GetMapping("/estudiantes/eliminar/{id}")Eliminar registro.

4. Controller: el recepcionista del sistema

El controlador recibe la solicitud del usuario y decide qué hacer. No debería hacer todo el trabajo pesado.

Analogía: El Controller es como la recepción de una entidad: recibe la solicitud y la dirige al área correcta.
// Esta clase será un controlador web @Controller public class EstudianteController { // El controlador necesita un servicio para procesar la lógica private final EstudianteService estudianteService; // Spring entrega automáticamente el servicio al controlador public EstudianteController(EstudianteService estudianteService) { this.estudianteService = estudianteService; } // Cuando el usuario entra a /estudiantes, se ejecuta este método @GetMapping("/estudiantes") public String listar(Model model) { // Se consulta la lista de estudiantes por medio del servicio model.addAttribute("lista", estudianteService.listarTodos()); // Se muestra la vista estudiantes.html return "estudiantes"; } }
Idea sencilla: el Controller recibe la ruta, conversa con el Service y devuelve una vista.

5. Service: donde vive la lógica del negocio

El servicio procesa reglas. Por ejemplo: validar si un nombre está vacío, convertir datos, hacer cálculos o decidir si algo se puede guardar.

Regla del negocioLenguaje naturalEjemplo en Service
Validar nombre“No puedo guardar un estudiante sin nombre”.if(nombre == null || nombre.isBlank())
Validar correo“El correo debe tener @”.if(!correo.contains("@"))
Listar“Traiga todos los estudiantes”.repository.findAll()
Guardar“Guarde este estudiante”.repository.save(estudiante)
@Service public class EstudianteService { private final EstudianteRepository estudianteRepository; public EstudianteService(EstudianteRepository estudianteRepository) { this.estudianteRepository = estudianteRepository; } public Estudiante guardar(Estudiante estudiante) { // Validación sencilla antes de guardar if(estudiante.getNombre() == null || estudiante.getNombre().isBlank()) { throw new RuntimeException("El nombre es obligatorio"); } // Si todo está bien, se guarda en la base de datos return estudianteRepository.save(estudiante); } }
